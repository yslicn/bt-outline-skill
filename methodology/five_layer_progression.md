# 五层递进结构（唯一规则源）

任何一份访谈提纲必须含 P1-P5 五个阶段，顺序不可变、不可裁剪（用户明确豁免并记录例外除外）。

| Phase | 名称 | 颜色语义 | 页面呈现 | 目的 |
|---|---|---|---|---|
| P1 | 暖场破冰 | 黄 #F1C21B / 文字 #8E6A00 | 直列问题，不分块 | 建立信任，获取组织/人员/协同结构信息 |
| P2 | 业务全景 | 青 var(--ibm-teal-50) | 必须用 discussion-block 分能力域 | 让客户"有话说"，梳理业务目标/核心流程/关键指标 |
| P3 | 流程深挖 | 蓝 #0F62FE 圆点 / 文字 #0043CE | discussion-block 或直列均可 | 沿协同链路追问细节，暴露断点与管理盲区 |
| P4 | 痛点唤醒 | 红 var(--ibm-red-60) | 直列问题，不分块 | 行业对比/跨域类比/后果推演，让客户自己发现问题 |
| P5 | 变革期望 | 绿 var(--ibm-green-50) | 直列问题，不分块 | 从痛点自然过渡到变革诉求，由客户主动提出方向 |

## 呈现规则

- 每个 Phase 由三要素组成：`phase-label`（圆点 + "Phase N · 名称"）、`phase-title`（阶段主题）、`phase-desc`（斜体目的说明）。
- P2 的 discussion-block 必须有 `area_num`（方块数字）+ `area_title` + `capability-ref`；P1/P4/P5 不得用 discussion-block。
- 每场结尾必须有"本场访谈预期输出" box（4-6 条 bullet），让访谈结束即形成结构化资产。

## 分层递进的写作约束

- 破冰不直接问战略，全景不问审批细节，深挖不重复全景，唤醒不提前给结论，期望不替客户做决策。
- 前一层问不到的信息，后一层不负责补；每层只收集该层定位的信息。
