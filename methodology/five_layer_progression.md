# 五层递进结构（唯一规则源）

每份提纲含P1-P5，顺序不变（用户明确豁免并记录例外除外）。五层提供采集结构，不要求必须发现痛点或提出变革；所有层遵循 `neutral_questioning.md`。

| Phase | 名称 | 颜色语义 | 页面呈现 | 目的 |
|---|---|---|---|---|
| P1 | 暖场与职责了解 | 黄 #F1C21B / 文字 #8E6A00 | 直列问题，不分块 | 建立信任，了解实际职责、人员安排和协作角色 |
| P2 | 业务全景 | 青 var(--ibm-teal-50) | 必须用 discussion-block 分能力域 | 让客户"有话说"，梳理业务目标/核心流程/关键指标 |
| P3 | 运行机制与具体案例 | 蓝 #0F62FE 圆点 / 文字 #0043CE | discussion-block 或直列均可 | 了解实际流转、正常与例外处理、信息使用和协作接口 |
| P4 | 挑战与机会探索 | 红 var(--ibm-red-60) | 直列问题，不分块 | 核实挑战、机会、适用边界和其他解释；允许无问题或不适用 |
| P5 | 保留与改进期望 | 绿 var(--ibm-green-50) | 直列问题，不分块 | 了解值得保留的安排、希望改善之处、条件和暂不调整的理由 |

## 呈现规则

- 每个 Phase 由三要素组成：`phase-label`（圆点 + "Phase N · 名称"）、`phase-title`（阶段主题）、`phase-desc`（斜体目的说明）。
- P2 的 discussion-block 必须有 `area_num`（方块数字）+ `area_title` + `capability-ref`；P1/P4/P5 不得用 discussion-block。
- 预期输出描述希望采集的信息，可包含有效做法、差异、未知和约束，不承诺形成痛点或方案；4-6条为建议密度，不得凑结论。
- 内部枚举intro/panorama/deepdive/awaken/expectation保持兼容；awaken表示挑战与机会探索。客户版隐藏Phase序号和内部映射，访谈员版保留。

## 分层递进的写作约束

- 从易答现状逐步到案例、挑战或机会、保留与改进。现场允许澄清、回看前层和跳过不适用追问，不为层定位压制真实回答。
- 没有挑战时，P4了解有效机制及适用条件，P5了解保持现状或应对未来变化的条件；不强行寻找缺陷。
