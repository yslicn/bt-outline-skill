# 问题分层写作规则

所有层必须遵循 `neutral_questioning.md`。主问、probe、背景、标题、预期信息与预期输出均不得夹带未经证实的事实、因果、责任或方案判断。

## 引导词规则（机器门强制）

- **P4（挑战与机会探索）的问题 probe 用"引导思考"**；标签不代表问题中立。
- **P1/P2/P3/P5 的问题 probe 一律用"追问"**。
- probe 允许为 0 个或多个，但类型必须符合所在层的规则；违反即机器校验拒绝。

## 五类问题的写作定位

| 层 | 问题定位 | 写作要点 |
|---|---|---|
| 暖场（P1） | 职责、人员安排与协作角色 | 先问“您主要负责哪些业务？”，再按实际安排了解人员、分工与协作。不默认存在独立团队、委员会或特定岗位 |
| 全景（P2） | 业务目标/核心流程/关键指标 | 让客户"有话说"。按能力域分块，每块问目标+流程+指标 |
| 案例（P3） | 实际流转、正常与例外处理、协作接口 | 描述近期案例，了解谁接手、怎样处理、使用哪些信息；不预设断点或失职 |
| 探索（P4） | 挑战、机会与适用边界 | 先核实相关性，允许没有问题、不适用或不同解释；有来源的行业参考仅作可选比较 |
| 期望（P5） | 保留、改进、条件与暂不调整理由 | 同时采集有效做法和改善意愿，不默认需要变革或某种方案正确 |

## 写作纪律

- 问题必须贴近该访谈对象能真实回答的范围，避免顾问黑话。
- 正文围绕一个核心信息目标，能自然口头问出；交代业务对象、所处情境或具体环节，以及希望了解什么。单点不等于一句极短的泛问，不能靠被隐藏的追问补全含义。
- 客户需要的中立背景放进可见`context`，回答范围或示例放进可见`answer_hints`；顾问假设、核实项和分支判断才放进内部`interviewer_context`与probe。
- 每问题至少标注 1 个价值流引用 + 1 个 L2/L3 能力引用（机器门校验引用存在于基底）。
- 不做事实、因果、责任或方案预设；主问温和但probe指控也不合格。

## 描述清楚的主问、回答提示与条件追问

- 每题有稳定`id`。允许主问配业务铺垫、中文术语括注与①②③等回答维度；不强制统一句式。同一信息目标下的枚举可留在主问或answer_hints，不应一律迁入隐藏的probe。独立疑问与需特定回答触发的追问才拆为probe。
- 不追求越短越好，不用“匹配是什么情况”“关系怎样核算”“有没有费劲的地方”“想达到什么水平”等脱离对象和范围的泛问。明确正在问哪个业务决策、处理过程或衡量对象。
- P2-P5逐题做“只看客户版能否回答”检查：若客户需反问“你指哪方面、要说什么”，补中立context/answer_hints，或重写主问。P1简单职责问题可无提示；主問已完整也不强制填满字段。
- `context`用于说明讨论的场景、对象、时间范围或必要术语，不陈述未证实的客户缺陷；无需背景时省略。`answer_hints`是可选的回答范围或普通例子，使用“例如、可结合、按实际做法”等开放表述。不要让客户必须采用列出的机制、指标或原因。
- 回答提示可以包含同一信息目标下的多个维度，不另塞多个独立问题。必要细节分成按回答选用的probe；不恢复长篇行业断言加多重质询的句式。
- 新提纲每个probe填`when`：`always`（一般追问）、`confirmed`（前提确认）、`denied`（前提否定）、`unknown`（尚不清楚）。confirmed须填`condition`说明具体触发回答。
- 现象确认后才能问原因与影响；否定后问实际做法或有效机制；未知时登记核实项。data gap不等于客户管理缺陷。
- 未核实的机制、岗位、数字先了解实际情况。术语按对象分级：先给中文解释，再使用熟悉的缩写；计划/信息化对象可讨论APS（高级计划与排程）、ATP（可承诺量）/CTP（可承诺产能）。先询问是否采用及实际支撑范围，不把提到术语写成客户已采用该机制。不熟悉的对象使用业务描述。
- P4可用有来源、范围明确的行业做法作比较；也可明确提出“供讨论的一种做法/假设场景”作为锚点。锚点后中性询问当前方式、适用条件和差异，不据此断定客户落后或有问题。“行业参考”标签本身不能证明资料真实。
- P5保留具体选项帮助收敛，例如信息依据、系统支撑、排产规则、变更协同；选项为参考范围，要允许其他方向、维持现状和暂不调整。不能把采用某系统预设为正确答案。
- probe.text不自带type前缀。条件标签、“如有”及内部提示不能代替语义审查。

## v1.2质量基准：完整但中立

- 含糊：“产能和交付之间的匹配，目前是什么情况？”
- 主问：“制定下一周的排产计划时，怎样判断各工序或产线能够完成的工作量？”
- context：“可选择一条熟悉的产线，说明安排下一周订单前怎样估算可以排入的任务。”
- answer_hints：“例如可结合已有订单、可开机时间、换型准备、工序速度或物料到位情况，介绍实际采用的判断依据；其他做法也可以。”

检验标准为客户明确知道讨论对象与回答范围，而非字数、提示条数或是否出现问号。客户版不能只剩抽象短问。
