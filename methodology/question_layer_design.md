# 问题分层写作规则

每层问题有明确的写作定位。问题正文之后必须有 probe（追问/引导思考），引导词规则是硬门。

## 引导词规则（机器门强制）

- **P4（痛点唤醒）的问题 probe 一律用"引导思考"**。
- **P1/P2/P3/P5 的问题 probe 一律用"追问"**。
- probe 允许为 0 个或多个，但类型必须符合所在层的规则；违反即机器校验拒绝。

## 五类问题的写作定位

| 层 | 问题定位 | 写作要点 |
|---|---|---|
| 破冰（P1） | 组织架构/人员规模/协同模式概览 | **先易后难，强制顺序：团队人数 → 组织架构/职能模块 → 职责分工边界 → 协同模式**。第一问必须是"您分管的业务，团队大概多少人、组织架构怎么划分"这类结构化、无压力、一句话能答的问题；不得第一问就触及业务战略、协同链条或决策链条。追问协同频率、决策链条放在本层末尾 |
| 全景（P2） | 业务目标/核心流程/关键指标 | 让客户"有话说"。按能力域分块，每块问目标+流程+指标 |
| 深挖（P3） | 协同链路断点、审批/系统/数据细节 | 沿链路追问具体细节：谁拍板、什么系统、多久、断在哪 |
| 唤醒（P4） | 行业对比/跨域类比/后果推演 | 先陈述行业普遍现象，再让客户对号入座；用"引导思考"给思考方向而非直接下结论 |
| 期望（P5） | 从痛点自然过渡到变革诉求 | 由客户主动提出改进方向；追问前提条件、阻力、红线 |

## 写作纪律

- 问题必须贴近该访谈对象能真实回答的范围，避免顾问黑话。
- 正文一句话能说清；需要铺垫的上下文放进 probe 或 phase-desc，不写进问题正文。
- 每问题至少标注 1 个价值流引用 + 1 个 L2/L3 能力引用（机器门校验引用存在于基底）。
- 不做假设性预设：问题里不夹带"是不是因为 X"的结论，尤其 P4 唤醒层以陈述现象+引导思考呈现。

## 问题详细化规则（P2-P5 强制，P1 破冰保持简短）

顾问要能照着提纲直接访谈，因此 P2/P3/P4/P5 的问题正文必须"带足够多的枚举信息"，结构为：

1. **背景/语境铺垫**（1-2 句）：陈述业务语境或行业现象，具体到案例、数据或客户类型（如"铜板带行业高端产品认证周期长达1-2年""C18150高强高导牌号是800V端子溢价来源"）。
2. **主问句**：清晰的提问。
3. **枚举维度**（①②③ 列出 3-5 个可选方向/维度/对象），引导客户逐一回答，也方便顾问跟进。
4. **数据源/示例提示**（可选，括注或追问）：如"（可选参考：安泰科/SMM、券商研报、客户走访反馈）"。

例外与强制：
- **P1 破冰必须保持简短**（先易后难，团队人数/组织/职责），不适用详细化。
- **P4 唤醒**：背景铺垫必须陈述真实行业现象（可带行业参考数据，须标注"行业参考"避免数据诚实风险），然后让客户对号入座。
- **probe.text 不得自带 type 前缀**（如不得写"引导思考：…"），type 由字段表达，渲染器自动加前缀。
