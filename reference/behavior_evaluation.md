# 中立提问行为回归（v1.1）

代码测试验证数据门和渲染，不验证大模型是否遵守中立提问。修改后用以下情形起草或重写问题，独立评审主问、probe、背景和预期输出；不得按痛点数量评分。

| 输入或反馈 | 合格行为 | 失败行为 |
|---|---|---|
| 只有业务目标，没有缺陷证据 | 正常采集现状和有效做法，strategic_tensions允许空 | 为满足结构凑出战略矛盾 |
| 行业资料描述交期压力 | 问本企业交期怎样确定，比较资料为可选 | 默认企业缺ATP/CTP或承诺靠拍脑袋 |
| 不清楚是否有独立预研团队 | 先问目前预研由哪些人员承担 | 直接问独立团队多少人 |
| 客户说维护安排一直有效 | 了解有效机制及适用条件 | 问TPM是真落地还是口号 |
| 客户说复盘后没有调整 | 了解维持安排的依据 | 定性为走形式 |
| 已核实一单延期 | 限定该订单，问过程和其他解释 | 扩大为管理失控或某部门失职 |
| 数字62%未核实 | 转内部核实项或去数字问现状 | 标行业参考后仍用作企业前提 |
| 财务团队多人访谈 | 问计算、核对和异常处理机制 | 逼公开认领坏账教训或断链风险 |
| 受访者否定顾问解释 | 允许否定，收集替代解释和可核实信息 | 当作掩饰或认知不足 |
| 四个枚举子问混在正文 | 一个短主问，多条按需追问 | 要求整段照读 |
| 外部机构仅在相关方清单 | 标待协调对象或资料渠道 | 自动列成已安排的受访对象 |
| 评审点名主问/probe预设 | 修改相应正文，按问题ID复核 | 只改页眉后声称完成 |

每例检查：前提是否有支撑、是否限定适用范围、否定/未知是否能继续、是否自然口头可问、是否暗含责任或方案判断。主问温和而probe预设损失也判失败。用其他行业追加例子，避免只对某一个项目的措辞有效。

本文件为后续模型生成评测协议，不能当作评测已经执行或已获得通过率的证据。实际运行时另存输入、生成结果、独立评审和版本信息。
